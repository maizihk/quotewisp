# 下一阶段开发计划：SQLite 单实例（建议 1.4）

状态：本轮已实现默认 SQLite、自动迁移、首次示例与空库支持，以及后台双格式导入、预览确认、异步任务和持久化提交结果。本文件保留完整阶段目标，已实现行为以 README 和测试为准；本地实现不代表旧发布镜像已支持。

目标：首次部署只需一个应用容器、一个持久化数据目录和端口映射；管理员初始化后，可在后台添加句库。当前镜像尚不支持本计划的新功能。

## 默认运行形态

生产默认使用 SQLite 单实例，数据库文件与现有密钥共同位于 `DATA_DIR`，默认仍为 `/var/lib/quotewisp`，不改为 `/data`。外部 MySQL/MariaDB 继续可选，现有四项 `DB_*` 配置和旧 `MYSQL_DSN` 均兼容；配置错误时明确失败，不从错误的 MySQL 静默回落 SQLite。

读路径继续使用内存快照。内存只作为运行指导，不设置句库总量门槛。SQLite 使用 WAL、本地磁盘和单写短事务，设置合理 busy 超时；不把 MariaDB 的 `FOR UPDATE` 原样复制到 SQLite。SQLite 与 MariaDB 共享同一业务契约测试。

| 配置状态 | 行为 |
| --- | --- |
| 未设置数据库变量 | 默认 SQLite，文件固定为 `DATA_DIR/quotewisp.db`，不增加必填环境变量 |
| 完整四项 `DB_HOST`、`DB_NAME`、`DB_USER`、`DB_PASSWORD` | 使用 MySQL/MariaDB |
| 旧 `MYSQL_DSN` | 使用 MySQL/MariaDB，继续兼容 |
| 部分四项或新旧配置混用 | 直接失败 |

本轮不增加 `DB_DRIVER` 或其他选择开关。

首次启动自动迁移，并写入少量自编示例。用事务标记 seed 已完成，不按 `count=0` 重复写入；管理员删除全部数据后不会再次复活。空库是合法状态：快照可用、`ready` 返回 200、随机查询无匹配时返回 404，前台和后台仍可用。数据库不可用且没有有效快照时启动失败；已有快照加载失败时保留旧快照并报告失败。

示例只写入全新初始化的数据库。已有数据库升级时，即使缺少初始化标记，也只记录初始化已完成，不混入示例或覆盖原数据。空库支持必须同时覆盖 API 快照和前台缓存，分类列表也允许为空；成功加载的空快照与加载失败、尚未加载是不同状态。`/readyz` 在空快照有效且未进入退出流程时返回 200，前台显示暂无语句和投稿入口，后台显示导入入口。

第三方 Hitokoto 语料只支持用户上传后离线导入，不自动下载，也不内置未授权语料。

首次启动时 SQLite 自动创建文件和表；外部数据库由部署方提供数据库与账号，程序只自动迁移表。数据库版本高于程序支持范围或迁移失败时退出，日志必须包含安全阶段和错误分类，不能只写 configuration 或 runtime；不得输出密码、DSN 或密钥。

迁移和 seed 使用数据库级互斥与幂等标记，两个并发首次启动不能重复写入。导入解析和校验在写事务外完成；正式导入使用单事务保证全有全无，大批量导入可长于普通短事务。其他写入超时时明确报告 busy，不丢弃数据，也不引入任务平台。

## 导入与管理

后台管理员可导入原生 JSON 和 Hitokoto 语句 JSON，统一复用现有导入校验服务。预览显示总数、新增、重复、冲突和错误位置；文件内及库内相同 UUID 且字段一致的记录跳过，不同字段报冲突且不覆盖。全重复无变更时不递增版本；确有变更时在事务末尾仅递增 1。UTF-8 长度由 Go 计算，正式事务内重新校验；写入成功但刷新失败时必须分别报告两种结果。

Hitokoto JSON 第一版将 `uuid`、`hitokoto`、`type`、`from`、`from_who` 分别映射到 `uuid`、`content`、`category`、`source`、`author`，忽略外部 `id` 和 `length`，使用 `utf8.RuneCountInString` 重算长度。分类缺失时预览明确显示待创建映射，不默认为错误分类；第一版只接受 JSON，不接受 ZIP 或下载。原生 JSON 仍执行严格校验，适配层不得放宽。

管理员鉴权继续要求 CSRF。上传文件使用私有临时目录，按到期、失败和进程重启清理；上传限制作为独立且可配置的资源限制，不复用内存句库总量限制。预览与确认绑定文件摘要和用户，一次性防止重复提交。

同一实例只允许一个导入任务，不引入 Redis 或队列框架。长任务使用明确的异步状态，不能被 10 秒 HTTP 写超时截断。首个管理员通过部署者执行现有 `web admin create --password-stdin` 初始化，密码由标准输入提供；本轮不增加公网安装向导，不允许互联网访客抢注，也不设置默认密码。管理员改密码、重置密码和并发校验必须保持现有契约。

长任务绑定服务生命周期 context 和单 worker；刷新失败可单独重试刷新，不重复导入。进程中断后的提交结果必须按 UUID 或持久化结果核实，不能假报回滚。WAL 备份必须使用一致性备份机制或停止服务后复制，禁止运行中直接拷贝数据库文件。

## 权限、迁移与边界

named volume 应在首次运行前预置为非 root 用户可写；bind mount 需要一次性创建目录并授予运行 UID 权限。SQLite 迁移支持备份和可回滚计划，禁止自动降级。此阶段不自动把现有 MariaDB 数据迁移到 SQLite。

默认 Compose 使用命名卷，镜像预建的数据目录归运行用户所有，首次挂载空命名卷无需用户手动修权限。数据库文件、WAL/SHM 文件和密钥一起留在挂载目录，重建容器不得丢失。保留现有 bind mount 方式供需要直接管理宿主机文件的部署者使用。

## 分阶段交付

1. 适配现有 SQL 方言、事务和数据库特定迁移，完成 SQLite WAL、迁移、快照和 MariaDB/SQLite 契约测试；不引入 ORM、通用仓储框架，使用纯 Go 驱动并验证 `CGO_ENABLED=0` 构建。
2. 完成 seed 标记、空库行为、错误保留旧快照和权限初始化。
3. 完成后台双格式导入、预览确认、摘要绑定、异步任务和清理机制。
4. 完成管理员初始化保护、并发密码契约、备份回滚演练与文档。

## 可执行验收清单

- 空目录首次启动完成迁移并只写入一次自编示例。
- 已有数据库升级不插入示例、不更换密钥、不覆盖账号及站点设置；并发初始化不重复迁移或写入示例。
- 删除全部数据后重启不会重新 seed；空库仍 `ready=200`，随机无匹配返回 404。
- SQLite 文件和 secret 位于同一 `DATA_DIR`，named volume 与 bind mount 均能由非 root 进程写入。
- 错误数据库配置不会回落 SQLite；数据库不可用且无快照时失败，有效旧快照加载失败时保留旧快照。
- 原生 JSON 与 Hitokoto JSON 均可预览、确认和原子导入；UUID 冲突报错且不覆盖，重复确认被拒绝。
- 写入成功、刷新失败能分别观测；长任务不受 HTTP 写超时截断，同实例不会并发执行两个导入。
- 上传临时文件在成功、失败、过期和重启后清理，限制可独立配置。
- 首次管理员初始化只能完成一次且无默认密码；鉴权、CSRF、改密和重置并发测试通过。
- SQLite 与 MariaDB 契约测试结果一致，备份恢复和计划回滚可演练且不自动降级。
- 数据库高版本和迁移失败日志包含阶段与错误分类；WAL 备份通过一致性备份或停机复制验证。
- 导入中断后可按 UUID/持久结果核实提交状态，刷新可独立重试且不会重复导入。
- `go test ./...`、`go test -race ./...`、`go vet ./...` 通过；SQLite 集成测试不依赖外部服务、不能跳过，MariaDB 兼容验收必须实际连接测试库。
- 记录数据规模、硬件、Go 版本、并发数和持续时间；验证随机读取压测及导入期间的可用性，不以 SQLite 名称推断吞吐量，不因内存参考值拒绝数据。
