# 语句数据导入格式

登录后台后进入 `/admin/imports` 上传 JSON，选择原生格式或 Hitokoto 格式，预览通过后确认。CLI 继续只接受下文的原生格式。

本文件定义 `sentence-api import` 的输入和处理约定。服务、数据库、内存指导及验收要求见 [开发规格](development-spec.md)。先按项目 README 构建 `sentence-api`，再使用以下命令执行导入。

## 1. 命令

```text
sentence-api import --file sentences.json
sentence-api import --file sentences.json --dry-run
```

数据库仅使用 `DATA_DIR/quotewisp.db`，必须已完成迁移。CLI 导入与 dry-run 均访问该文件，dry-run 不写入业务数据；临时目录和数据目录需具备相应权限。

导入总期限由 `IMPORT_TIMEOUT` 控制，默认 120 秒，可按实际数据规模调整。CLI 不设置文件大小、语句条目数或分类条目数上限，不根据 API 内存参考值拒绝导入。流式解析文件并减少原始文件与解码数据的重复驻留；写入前仍完整校验全部数据。部署资源按实际导入规模配置。

## 2. JSON 格式

文件必须是 UTF-8 编码的单个 JSON 对象，不含 BOM。拒绝注释、尾随逗号、尾随其他 JSON 值、重复对象成员名、未知字段和非法 UTF-8。无效的 Unicode 代理项转义也必须拒绝，不能静默替换为替代字符。

字段名只接受下表规定的大小写。使用稳定标准库处理 JSON 语法，并在固定格式边界补充必要校验，不开发通用 JSON Schema 引擎，也不依赖实验性 JSON API。不能假定 `encoding/json` 默认已拒绝重复成员或非法 Unicode 转义；这些属于导入校验的明确测试项。参见 [Go JSON 解码行为](https://pkg.go.dev/encoding/json#Unmarshal)。

```json
{
  "categories": [
    {
      "code": "original",
      "name": "原创",
      "sort_order": 0
    }
  ],
  "sentences": [
    {
      "uuid": "75a45fd4-4f2f-45eb-80cb-6f0a7bcdfaf2",
      "category": "original",
      "content": "今天也要认真写代码。",
      "source": "项目自编示例",
      "author": null
    }
  ]
}
```

此示例由项目自编，不属于第三方句库。

### 2.1 顶层字段

| 字段 | 必填 | 类型 | 约束 |
| --- | --- | --- | --- |
| `categories` | 否 | 对象数组 | 省略或空数组表示不创建分类，不接受 `null` |
| `sentences` | 是 | 对象数组 | 至少一条，不设置条数上限 |

首版不提供仅导入分类的文件。首次部署可在同一文件中同时定义分类和语句。

### 2.2 分类字段

| 字段 | 必填 | 类型 | 约束 |
| --- | --- | --- | --- |
| `code` | 是 | 字符串 | 匹配 `^[a-z0-9][a-z0-9_-]{0,31}$` |
| `name` | 是 | 字符串 | 1–64 个 Unicode 码点，最多 256 字节，不能全为空白 |
| `sort_order` | 否 | JSON 整数 | 默认 0，范围为有符号 32 位整数 |

新分类统一创建为启用状态。禁止提交 `id`、`enabled`、创建时间和更新时间等字段。

同一文件中分类代码不得重复，即使定义相同也报错，以避免名称或顺序定义歧义。

对于数据库已有分类：

- 分类必须启用。
- 若文件提交了该分类定义，名称和排序值必须与数据库一致；省略 `sort_order` 按默认 0 比较。
- 不允许借导入隐式更名、改变排序或启用停用分类。
- 已有分类可以不出现在 `categories` 中，直接被语句引用。

### 2.3 语句字段

| 字段 | 必填 | 类型 | 约束 |
| --- | --- | --- | --- |
| `uuid` | 是 | 字符串 | 标准带连字符 36 字符 UUID，可含大小写十六进制，存储前统一小写 |
| `category` | 是 | 字符串 | 合法分类代码，必须引用已启用分类或文件中新定义的分类 |
| `content` | 是 | 字符串 | 非空且不能全为空白，符合现有 `TEXT` 字段的 65535 字节容量及 `length` 表示范围 |
| `source` | 否 | 字符串或 `null` | 最多 255 个码点、1020 字节 |
| `author` | 否 | 字符串或 `null` | 最多 128 个码点、512 字节 |

规则：

- 所有字符串必须为有效 UTF-8。不 trim 内容、不转换分类代码大小写、不做 Unicode 归一化。
- UUID 不接受 32 位无连字符、URN 或花括号形式，不额外限定版本。
- `source`、`author` 的省略、`null` 和空字符串在比较及 API 输出时均视为空字符串，导入持久化时统一使用数据库 `NULL`。
- `id`、`length`、`status`、`created_at`、`updated_at`、`published_at` 以及已移除的旧响应字段 `hitokoto`、`type`、`from`、`from_who` 均不允许提交。
- 长度由 Go 的 `utf8.RuneCountInString(content)` 计算，包含空格、标点和换行。
- 随机接口的 1000 码点参数上限不限制导入内容长度；更长且满足数据库字段约束的记录可以导入、加载并通过 UUID 查询。
- 新增语句统一为 `status = 1`，设置 UTC 发布时间。需要审核的数据应通过外部管理流程处理，不使用本导入命令。

## 3. 去重与冲突

去重键是规范化为小写标准形式的 UUID。

业务字段比较包括 `category`、`content`、规范化后的 `source`、`author`。分类与内容按字节精确比较，不依赖语言排序规则；计算长度也必须相同。

| 情况 | 行为 |
| --- | --- |
| 文件内 UUID 不同 | 分别处理 |
| 文件内 UUID 相同且业务字段完全相同 | 合并为一条，记录去重数 |
| 文件内 UUID 相同但业务字段不同 | 整批失败，不写入 |
| 数据库不存在 UUID | 计划新增 |
| 数据库已有 UUID，处于已发布状态、分类启用、长度正确、发布时间存在，且业务字段相同 | 跳过并计数，不改变原记录或时间 |
| 数据库已有 UUID，但状态、分类、长度、发布时间或业务字段不满足上一行条件 | 整批失败，不覆盖、不发布、不复活 |
| 引用未知分类且文件未定义 | 整批失败 |
| 引用已有但停用的分类 | 整批失败 |

首版不提供 `--overwrite`、隐式 upsert 或部分成功模式。需要修改已有记录时，由外部管理程序在事务中完成并递增版本。

与本次输入关联的已有记录存在非标准 UUID、错误长度等损坏时，按冲突处理，不能误认成可安全跳过。导入不逐条检查无关记录；全库业务数据完整性由快照加载验证。

## 4. 执行与事务

1. 流式解析 JSON，完整校验文件结构、所有字段和文件内去重关系，不按文件大小或记录总量拒绝输入。
2. 连接目标数据库，确认 schema 版本为 1 至 5 且非 dirty。
3. 开始单个事务，使用 `BEGIN IMMEDIATE` 串行化写入，读取 `dataset_versions.id = 1` 的有效版本。
4. 检查本次文件引用的分类与 UUID。遵守协议的写入已经通过 SQLite 写事务串行化，不另建一套细粒度锁调度机制。
5. 创建新增分类，分批插入新增语句。新 ID 由数据库生成；分批 SQL 不分批提交，不执行用于内存准入的全库总量检查。
6. 有实际新增分类或语句时，在同一事务末尾递增版本一次，并检查版本行更新成功。
7. 提交事务并在确认成功后输出摘要；提交前任何错误都回滚全部新增分类、语句和版本变更。

提交前发生锁等待超时、上下文取消或唯一约束失败时回滚。写入必须在同一事务中修改数据并递增版本，保持事务原子性。

若发送 COMMIT 后连接中断或无法收到确认，提交结果可能不确定。此时返回非零并使用 `commit-outcome-unknown` 错误类别，不得声称已经回滚，也不得输出已确认成功的摘要。事务仍然是全有或全无；部署者可对同一文件执行 dry-run 后重试。若此前已提交，UUID 和分类的相同内容会被跳过，不重复写入或递增版本。

全部记录已存在且一致、也无新增分类时，命令成功，`changed=false`，版本不变。

导入不为检查容量扫描整个句库。导入成功表示事务已提交；API 随后独立进行完整快照加载，只有数据正确性校验通过才切换，不按内存参考值裁剪记录。

## 5. dry-run

`--dry-run` 执行文件校验，并通过同一个一致性事务检查相关分类及 UUID 冲突；不检查内存配额或数据总量，不校验整个句库，不修改业务数据。

- 不创建分类、不插入语句、不更新版本、不修改迁移状态。
- 使用读取到的数据库版本作为 `dataset_version_before`。
- 报告计划新增数，但不报告已经提交的新版本。
- 不锁定未来执行结果，不保证之后的正式导入仍会成功。
- 正式导入必须重新校验并处理期间出现的并发变更。

SQLite 文件不可用、数据库不兼容或连接失败时，dry-run 失败，不退化为仅文件校验后宣称通过。

## 6. 输出与退出码

成功向标准输出写一条 JSON 摘要，诊断日志写标准错误。示例：

```json
{
  "dry_run": false,
  "input_count": 3,
  "deduplicated_count": 1,
  "skipped_count": 1,
  "new_sentences": 1,
  "new_categories": 1,
  "changed": true,
  "dataset_version_before": "1",
  "dataset_version_after": "2"
}
```

- `input_count` 是原始语句条目数。
- `deduplicated_count` 是文件中被合并删除的重复条目数。
- `new_sentences`、`new_categories` 在 dry-run 中表示计划新增数，在正式成功输出中表示已提交的新增数，不同时维护两套计数字段。
- `input_count - deduplicated_count = skipped_count + new_sentences`。
- dry-run 中 `changed=false`、`dataset_version_after=null`；是否计划变更可由新增数判断。
- 正式无变化导入中，新增数为 0，前后版本相同，`changed=false`。
- 版本始终使用十进制字符串，计数使用 JSON 数字。
- 成功退出码为 0，参数、校验、数据库或超时错误为非零。
- 错误可包含字段名、记录索引和固定错误类别，不能输出密码、令牌、DSN 或整条语句内容。

## 7. 数据来源

部署者必须事先确认导入内容的许可证、授权范围和使用条件。本项目不自动下载第三方数据，不提供来源不明或 AGPL 语句库。导入成功不代表软件对数据使用权作出判断。

## 后台上传与 Hitokoto 格式

上传限制由 `IMPORT_MAX_UPLOAD_BYTES` 配置，默认 33554432 字节（32 MiB），最多 1 GiB；与句库总量无关。`IMPORT_UPLOAD_TTL` 默认 30 分钟，`IMPORT_TIMEOUT` 默认 120 秒。上传完成后，解析、预览和正式导入由单个后台 worker 执行；同一实例仅允许一个待确认或执行中的任务。确认前可取消预览。

Hitokoto 输入为 JSON 对象数组，例如：

```json
[{"uuid":"930bb316-a56b-49b5-879e-a322271c91de","hitokoto":"这是用户自行提供的示例。","type":"a","from":"示例","from_who":null}]
```

`uuid`、`hitokoto`、`type` 必填，分别映射到原生 `uuid`、`content`、`category`；`from` 和 `from_who` 映射到来源和作者。忽略外部 `id`、`length` 及其他元数据，长度重新计算；重复 JSON 成员、无效 Unicode、UUID 或字段类型仍会拒绝。已有分类沿用本地名称和排序，缺失分类以 `Hitokoto · <type>` 命名并在预览中列出。支持 JSON 文件，不支持 ZIP 或 URL 下载。

预览列出文件内重复、库内重复、新增数量及分类映射。校验遇到首个冲突或错误时停止，并显示可定位的错误；不承诺汇总所有错误。确认绑定当前管理员、文件 SHA-256 和有效期限；正式导入重新校验，重复确认会被拒绝。预览统计不保证正式执行结果，期间的数据库修改可能导致冲突。

上传文件保存在 `DATA_DIR/imports/uploads` 私有目录，完成、失败、取消、到期和重启时清理。任务记录保存在数据库中，后台显示当前管理员最近 50 条记录。数据与提交结果在同一事务中写入；刷新失败保留已提交结果，可单独重试刷新，不重复导入。服务重启后，已提交任务显示待重试刷新，未提交任务显示中断并要求重新上传。提交结果暂时无法核实时保留处理中状态，恢复数据库并重启后核实结果。

该任务管理器面向单应用实例；不要让多个进程共用同一任务数据库和上传目录。升级前按数据库类型完成一致性备份。
